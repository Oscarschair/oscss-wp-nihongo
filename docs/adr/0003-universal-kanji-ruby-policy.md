# 0003: 外国人学習者向け全記事・全漢字へのHTML5ルビ（<ruby><rt>）標準適用方針

- **日付**: 2026-09-22
- **ステータス**: 承認済み (Accepted)
- **決定者**: 開発チーム・プロダクトオーナー
- **対象**: `content/posts/*.md`, `assets/css/main.css`, `scripts/core/`

---

## コンテキスト (Context)

Webメディア「[オスカーの日本語学習帳](https://nihongo.oscarchair.jp/)」は、日本文化や生きた日本語を学ぶ外国人学習者・多言語話者を主対象読者としている。

従来の運用では、一部の難読漢字や重要語句のみにカッコ書き（例: `替え玉（かえだま）`）やセリフ直下のひらがな行（例: `（すみません、おひやは どこに ありますか？）`）を付与していた。しかし、以下の課題が生じていた：

1. **外国人学習者の読書体験（UX）の阻害**:
   - JLPTレベル（N5〜N1）に関わらず、日常の漢字（「席」「空く」「使う」など）であっても読み方が分からないと読者が検索に手間取り、記事から離脱してしまう。
2. **タイポグラフィ崩れと二重ルビ問題**:
   - 単語全体にルビタグを付与すると、送り仮名や接頭辞（ひらがな・カタカナ）の頭上にもルビが重なり（例: 「太っている」の「っている」の上に「っている」が乗る、カタカナ「エプロン」の上に「えぷろん」が乗る）、視覚的ノイズとレイアウト崩れを引き起こしていた。
3. **不要な重複による縦スクロールの肥大化**:
   - ルビとカッコ読みが共存することで同一情報が二重に表示され、特にスマートフォン（SP）閲覧時における不要なスクロール負荷を招いていた。

---

## 決定事項 (Decision)

すべての外国人学習者が辞書なしでストレスフリーに読めるメディアを目指し、以下の「全漢字ルビ標準化アーキテクチャ」を正式策定・適用する。

### 1. 全記事・全漢字へのルビ標準化
記事本文内に出現するすべての漢字に対して、HTML5標準の `<ruby>漢字<rt>ふりがな</rt></ruby>` を適用する。

### 2. 漢字限定ルビ原則 (Kanji-Only Strict Rule)
ひらがな・カタカナ・アルファベット・記号の頭上には一切ルビを載せず、**純粋な漢字部分のみを `<ruby>` で囲む**ことを絶対ルールとする。

- **送り仮名**:
  - ⭕️ `<ruby>太<rt>ふと</rt></ruby>る` （❌ `<ruby>太る<rt>ふとる</rt></ruby>`）
  - ⭕️ `<ruby>太<rt>ふと</rt></ruby>っている` （❌ `<ruby>太っている<rt>ふとっている</rt></ruby>`）
  - ⭕️ `<ruby>少<rt>すこ</rt></ruby>し` （❌ `<ruby>少し<rt>すこし</rt></ruby>`）
  - ⭕️ `<ruby>替<rt>か</rt></ruby>え<ruby>玉<rt>だま</rt></ruby>` （❌ `<ruby>替え玉<rt>かえだま</rt></ruby>`）
- **接頭辞・接尾辞**:
  - ⭕️ `お<ruby>冷<rt>ひや</rt></ruby>` （❌ `<ruby>お冷<rt>おひや</rt></ruby>`）
  - ⭕️ `お<ruby>会計<rt>かいけい</rt></ruby>` （❌ `<ruby>お会計<rt>おかいけい</rt></ruby>`）
  - ⭕️ `お<ruby>通<rt>とお</rt></ruby>し` （❌ `<ruby>お通し<rt>おとおし</rt></ruby>`）
  - ⭕️ `さび<ruby>抜<rt>ぬ</rt></ruby>き` （❌ `<ruby>さび抜き<rt>さびぬき</rt></ruby>`）
- **外来語・カタカナ混在語**:
  - ⭕️ `<ruby>紙<rt>かみ</rt></ruby>エプロン` （❌ `<ruby>紙エプロン<rt>かみえぷろん</rt></ruby>`）

### 3. 重複するカッコ読み行の全廃
漢字自体にルビが振られるため、セリフやフレーズの直下に併記されていた全体ひらがな読み行（例: `> （さきに せきを とっても いいですか？）`）は完全に不要・重複とみなし、すべて削除・廃止する。

### 4. ルビースタイリング仕様の統一 ([assets/css/main.css](file:///c:/Users/user/git/oscss-wp-nihongo/assets/css/main.css))
```css
ruby {
	ruby-position: over;
	ruby-align: center;
	display: inline-ruby;
}

rt {
	font-size: 0.62em;
	color: var(--color-primary);
	font-weight: 600;
	letter-spacing: 0.02em;
	line-height: 1;
	user-select: none; /* コピペ時にルビ文字が混入するのを防止 */
}
```
- `user-select: none;` により、学習者が本文を範囲選択してクリップボードにコピーした際、ルビ文字が混入して外部辞書検索が壊れることを防止する。

### 5. 自動変換・Gutenberg同期パイプラインの運用
- マークダウン作成・編集時およびビルド時に、漢字のみルビ変換スクリプト（`scripts/core/convert_pronunciations_to_ruby.py`, `scripts/core/refine_kanji_only_rubies.py`）を実行。
- `scripts/core/repair_all_posts_gutenberg.py` を経由して、HTML5 `<ruby>` タグを含むGutenbergブロックHTMLを本番WordPressへ自動同期する。

## 影響・結果 (Consequences)

### メリット (Positive)
- **高いアクセシビリティ**: 漢字圏外（英語圏・東南アジア・欧州等）の初級学習者から上級者まで、誰でも辞書なしで記事を楽しめる。
- **洗練されたタイポグラフィ**: ひらがな上の重複ルビが完全に排除され、美しく正確な日本語組版を実現。
- **SP閲覧の最適化**: 重複するカッコ行が削除されたことで、縦スクロール量が削減されテンポよく読める。
- **学習UXの向上**: `user-select: none;` により、単語をコピーして外部学習アプリへ貼り付ける操作が快適。

### デメリット・トレードオフ (Negative / Trade-offs)
- **HTMLソースの増大**: `<ruby>` タグの増加により、HTMLサイズがわずかに増加する（LiteSpeedキャッシュとGzip/Brotli圧縮により実通信量への影響は極小）。
- **文脈依存の読み分け精度**: 同音異字・多音語（「行く」「方」「開く」など）の文脈判定において、辞書・スクリプトの継続的なメンテナンスが必要。
